# APP-3 API — correo DTE durable

## Resultado

La aceptación fiscal y la programación del correo ahora se confirman en la misma transacción de base de datos. Cuando un DTE queda `PROCESADO` y sellado, el backend crea como máximo una entrega automática `RECEPTOR` y una `EMISOR`. El Worker las procesa por separado; una falla de correo no altera el estado fiscal.

No se modificó Flutter ni la interfaz Razor en este incremento.

## Contrato API

- `GET /api/dte/documentos/{id}/correos` requiere `DTE.Consultar` y devuelve estado general, receptor, emisor e historial con destinatarios enmascarados.
- `POST /api/dte/documentos/{id}/correos/reenviar` requiere `DTE.Reenviar` y acepta `RECEPTOR`, `EMISOR` o `AMBOS` junto con una `idempotencyKey` de 8 a 100 caracteres seguros.
- El endpoint legacy `POST /api/dte/documentos/{id}/reenviar` se conserva por compatibilidad, pero ya no agrega CC ni BCC.

Estados: `NO_APLICA`, `SIN_REGISTRO`, `PENDIENTE`, `ENVIANDO`, `ENVIADO`, `REINTENTANDO` y `FALLIDO`.

`ENVIADO` confirma aceptación por el proveedor SMTP. Sin webhook del proveedor no representa lectura ni entrega final al buzón.

## Persistencia y seguridad

La migración `APP3_DteEmailOutbox` agrega a `Notif_Outbox` la identidad de entidad/finalidad y el `MessageId` del proveedor, además de un índice de consulta por empresa y DTE. Las claves automáticas incluyen empresa, documento y finalidad mediante la unicidad existente por empresa/clave.

- Todos los queries y comandos filtran `EmpresaId`.
- Receptor y emisor son mensajes independientes, incluso si usan la misma dirección.
- No se usa CC ni BCC.
- El error visible es sanitizado; no se persiste el detalle crudo del proveedor.
- No hay backfill automático de documentos históricos.

## Activación operativa

El código y la migración no habilitan el Worker por sí solos. Después de aplicar la migración y verificar la configuración SMTP por empresa, el runtime del Worker debe contener:

```json
{
  "Worker": {
    "Enabled": true,
    "NotificationOutbox": {
      "Enabled": true
    }
  }
}
```

Mantener deshabilitada la tarea durante la migración. Luego iniciar una sola instancia, emitir una factura controlada y comprobar las dos filas de outbox, los dos mensajes sin CC/BCC y las dos alertas independientes.

- No se enviaron correos reales ni se modificó la base de producción durante esta validación.
