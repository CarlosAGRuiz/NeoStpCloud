# Protected production readiness rehearsal

`New-ProtectedProductionClone.ps1` reads the API local connection only in memory, requires source `NeoSTP_Cloud` on engine 16, captures sanitized SHA-256/count fingerprints for the original columns except rowversion of 74 tables with direct EmpresaId, creates a new COPY_ONLY/CHECKSUM backup in a protected GUID subdirectory of the SQL Backup directory, verifies it, and restores to `NeoProductionAudit_<GUID>` on the same engine with new files and no REPLACE. It never changes source tables. Backup and restored files remain outside the repository under inherited restricted ACLs.

The C# executable requires that exact approved manifest and validates clone database name, engine and physical filenames before migrating or changing configuration. It exercises Production DatabaseStartup through isolated DI and a command interceptor forbidding writes: schema 79 must reject; an explicit separate clone migration to 89 must pass. No host, worker, network client, bootstrap or seeder runs.

The sole business-data rehearsal edit changes cloned NEO 2 fiscal configuration to PRODUCCION and clears cached token/test password. It does not authenticate or sign. The harness checks that PRUEBAS document context cannot be reused, client 23 stays PRUEBAS with STARTERFE/exactly CORE and NEODTE active, NEO resolves valid Enterprise with 18 active modules, original tenant fingerprints remain unchanged except the intended NEO configuration edit, and the active source stays at 79 migrations with identical fingerprints.

Manifest/results go under ignored `tmp/neo-production/`; no customer rows, credentials or connection strings are emitted. Source and clone fingerprints cover tables with direct EmpresaId and preserve original column lists across migrations; rowversion columns are excluded. The executable retains its clone. Separately authorized Remove-OwnedProductionClones.ps1 checks successful 22-check evidence and exact GUID/database/engine/physical paths before dropping only the two owned copies; it preserves the verified backup. Restore-VerifiedBackupClone.ps1 reuses the verified backup for a fresh GUID rehearsal without another source backup. The archived attempt2 manifest is its explicit baseline; these scripts are scoped to this rehearsal and must not be run against another manifest implicitly.

Build and execution require the coordinator's explicit migration slot. Never direct this executable or EF migration to the active source. The rehearsal does not constitute an actual production environment switch or Hacienda credential verification.

Final rehearsal on 2026-09-05 passed 22/22 on SQL Server 2022 engine 16: copy 79 to 89 migrations, both startup modes read-only, DBCC table results zero rows/zero errors, fiscal clone isolation and effective plans verified. Both copies were subsequently removed with exact guards; source remains 79 and source tenant fingerprints were identical throughout the rehearsal. Backup remains protected outside the repository. Earlier failed harness attempts are retained under logs/attempt1 and logs/attempt2: nullable empty-table digest handling and an incorrect STARTER expectation (actual STARTERFE). No source or product defect was hidden by the rerun.
